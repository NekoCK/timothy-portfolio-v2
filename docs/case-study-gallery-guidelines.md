# Case Study 圖片 Gallery 規範

狀態：已確認
確認日期：2026-08-19
適用範圍：Ferqo、IXT Insurance、OneSleeve、AlphaCamp，以及後續新增的 Case Study

## 目的

圖片排列應優先服務案例敘事與閱讀順序，不只依照原始圖片尺寸自動排版。不同專案與 Section 必須使用同一套版型邏輯，讓面試官能快速理解重點，同時保留圖片原始比例與細節。

## 固定尺寸與公式

- Case Study 圖片區最大內容寬度以實際容器寬度 `W` 為準；桌面版設計基準為 `1440px`。
- 圖片框之間的間距 `G = 24px`。
- 每個圖片框的內距 `P = 24px`。
- 圖片框背景色固定為白色 `#FFFFFF`。
- 同一排有 `N` 個圖片框時，每個圖片框寬度為：

  `cellWidth = (W - (N - 1) × G) / N`

以 `W = 1440px` 為例：

| 欄數 | 每格寬度 | 建議用途 |
| --- | ---: | --- |
| 1 | 1440px | 主視覺、總覽、高細節橫圖 |
| 2 | 708px | 比較圖、前後版本、同組流程（預設） |
| 3 | 464px | 比例相近、細節較少的同組圖片 |

不使用六張圖片同排的六欄版型，因為會犧牲可讀性與畫面秩序。

## 核心規則

1. 圖片一律維持原始比例，不拉伸、不變形、不任意裁切。
2. 圖片使用 `object-fit: contain`，置中顯示。
3. 同一排的圖片框必須等寬、等高；圖片比例不同時，以白色留白補足框內空間。
4. 同一排盡量只放方向與比例接近的圖片，例如橫圖配橫圖、直圖配直圖。
5. 有語意關係的圖片應放在同一組，例如 Before / After、Light / Dark、Flow Step 1 / Step 2。
6. 圖片的角色與閱讀順序優先於原始尺寸；自動排版只能提供建議，不能單靠寬高決定最終版型。
7. 不把圖片放大超過其自然尺寸，除非來源解析度足以支援目標顯示尺寸，以免再次產生模糊問題。
8. 單張直式圖片不強制拉滿全寬；使用適當 `max-width` 後置中顯示。
9. 圖片可搭配簡短 Caption，但 Caption 不應取代 Section 內的分析文字。
10. 圖片若只支撐單一小節，應掛在該小節並緊接於相關段落之後；只有開場、整段比較或總結型圖片才放在 Section Gallery。

## 可使用的版型

### `full`

單張圖片滿版顯示。適用於 Section 主圖、產品總覽、完整流程與高細節橫向圖片。

### `pair`

兩張圖片並排，是支援圖片的預設版型。適合比較、兩個產品、兩個版本或同一流程的兩個階段。

### `triptych`

三張圖片並排。只在三張圖片比例相近、資訊密度不高，而且確實屬於同一組時使用。

### `feature-grid`（4–6 張圖片的推薦版型）

先用一張主圖建立情境，再將支援圖片兩張一組。最後一張若為重要橫圖可滿版；若為直圖則限制寬度後置中。

六張圖的建議順序：

```text
[ 01 Feature／滿版主圖                         ]
[ 02 同組支援圖              ][ 03 同組支援圖  ]
[ 04 同組支援圖              ][ 05 同組支援圖  ]
[ 06 重要橫圖滿版，或直圖限制寬度後置中        ]
```

### `auto`

只用來產生初步建議。系統可依圖片方向、比例與數量提出分組，但發布前仍應由內容編輯者確認 `layout`、`role` 與 `group`。

## 最後一排與落單圖片

- 最後只剩一張橫圖：可使用 `full`，前提是解析度足夠且圖片具有總結作用。
- 最後只剩一張直圖：置中並設定 `max-width`，不要拉滿 1440px。
- 最後剩兩張比例差異過大：不要硬放同排；移動分組順序，或拆成兩個有敘事意義的圖片群組。
- 不為了填滿版面而混合無關圖片。

## 響應式規則

- 桌面版（`>= 1200px`）：依選定版型顯示，最多三欄。
- 平板版（`768–1199px`）：最多兩欄；原本三欄的版型可改為兩欄加一張置中或滿寬。
- 手機版（`< 768px`）：所有圖片改為單欄，保持 `24px` 間距與框內距。
- 各尺寸都必須維持圖片比例，不以裁切換取整齊。

## 後台欄位建議

每個 Section 與 Subsection 的 Gallery 都應允許新增任意數量圖片，並提供以下設定。Subsection 圖片沿用相同版型規則、24px 間距、24px 內距與白色圖片框：

| 欄位 | 建議值 | 用途 |
| --- | --- | --- |
| `layout` | `full`、`pair`、`triptych`、`feature-grid`、`auto` | 指定整個 Gallery 版型 |
| `role` | `feature`、`support`、`detail` | 決定圖片視覺優先級 |
| `group` | 自訂字串 | 指定應放在同一排或同一敘事群組的圖片 |
| `fit` | 預設 `contain` | 保留未來特殊需求，但 Case Study 預設不裁切 |
| `frameRatio` | `auto`、`16:10`、`4:3`、`3:4` | 讓同一排圖片框維持一致尺寸 |
| `maxWidth` | 選填像素值 | 限制單張直圖或低解析度圖片的最大寬度 |
| `background` | 預設 `#FFFFFF` | 圖片框背景 |
| `caption` | 選填文字 | 補充圖意，不承載主要論述 |

資料結構範例：

```json
{
  "gallery": {
    "layout": "feature-grid",
    "gap": 24,
    "padding": 24,
    "background": "#FFFFFF",
    "items": [
      {
        "asset": "cover.png",
        "role": "feature",
        "group": "overview",
        "fit": "contain",
        "frameRatio": "auto"
      },
      {
        "asset": "before.png",
        "role": "support",
        "group": "comparison",
        "fit": "contain",
        "frameRatio": "4:3"
      },
      {
        "asset": "after.png",
        "role": "support",
        "group": "comparison",
        "fit": "contain",
        "frameRatio": "4:3"
      }
    ]
  }
}
```

## 發布前檢查

- 圖片順序是否能支持 Section 的敘事？
- 主圖是否比支援圖更突出？
- 同排圖片是否屬於同一組、方向與比例是否接近？
- 同排圖片框是否等寬、等高？
- 圖片是否沒有被裁切、拉伸或變形？
- 圖片框是否為白底、內距是否為 24px、間距是否為 24px？
- 是否避免把低解析度圖片過度放大？
- 細節文字在實際顯示尺寸下是否仍可閱讀？
- 手機版是否正確轉為單欄？
